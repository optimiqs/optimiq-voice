# Repo-wide audit and fix pass — 2026-09-09

Baseline commit: 724d9f1 (the September 7–8 native-calling work, committed first). Every source file in
apps/* and packages/* was read by one of 13 parallel auditors, each owning a disjoint directory set;
13 fix agents then landed the findings area by area, followed by an integration wave for the items
that crossed area boundaries. Six commits, 6ccfef8..e5cc097, one per area.

## The P0s worth knowing about

Security

- SSO: tenant IdPs were registered platform-wide with account linking on. An org admin controlling
  an IdP could assert another tenant's email and take over that account.
- `moh_class.streamUri` was rendered unvalidated into `musiconhold.conf`; a newline injected an
  `application=` line that Asterisk executes.
- mediad built the recording directory from unvalidated `orgId`/`callId`, so `../../..` escaped the
  recordings root.
- sipd accepted a replayed REGISTER `Authorization` with a different Contact within the nonce TTL,
  forking a victim's inbound calls to the attacker.
- `branding.logoObjectKey` was caller-supplied and then served unauthenticated from the shared media
  root; SVG logos were served inline on the API origin.
- api and engine held `$JS.API.>` in `config/nats.conf`, which made their enumerated NATS grants
  decorative (stream delete/purge, and reads of every KV bucket including registrations).
- Effect defect logging and `Effect.log` annotations bypassed redaction entirely.
- Unmatched WebSocket upgrades were never destroyed once an upgrade listener existed: an
  unauthenticated fd leak. The provisioning rate limiter ran after the secret check.

Correctness

- sipd's carrier profile was unreachable in its own default configuration (no listener means never
  matched), so every carrier INVITE got an unanswerable digest challenge.
- The engine's AOR fallback applied to off-net follow-me hops, external destinations and external
  queue agents, resolving them against the tenant registrations bucket instead of the trunk.
- One tenant's first `allow` ACL row flipped the shared Asterisk ACL section to allowlist mode with
  `deny 0.0.0.0/0`, locking every other tenant's phones out.
- The projection outbox was discharged even when every KV put failed (trunks, DID index, SIP ACL,
  queue membership), so a failed publish was never retried.
- `PUT …/reorder` violated the unique `(parent, ordinal)` index on 7 of 8 reorderable collections.
- `/healthz` did not see the sipd dialog feed; a dead feed meant no leg ever ended while the pod
  reported healthy. Live media events were dispatched unordered per leg.
- `planNodeReferences` omitted four edge kinds, so closure and cycle checks were blind to queue exit,
  call-flow day/night, stream fallback and dial-by-name branches.
- mediad never reaped held or muted sessions (a ringing leg after an engine crash leaked its port
  pair until restart) and grew the playback index on every hold.
- A data race in sipd's reaper heartbeat read live dialog fields off the owning goroutine.

## Performance highlights

- mediad transcode hot path: 3 allocations / 1120 B per packet down to 1 / 160 B (measured).
  Mixer socket writes moved outside the conference mutex; allocator binds outside its mutex.
- Engine queue polling collapsed from `callers × agents` KV gets per second to one fan-out per roster
  per poll; `rankOf` is a counting pass instead of a full re-sort per caller; routing-artifact and
  roster caches are TTL + LRU bounded.
- sipd registrar sweep no longer does a KV round trip per binding every 5 s; credential cache has
  O(1) eviction and single-flight; ACL replay compiles once instead of once per record.
- API: 21 serial per-delete existence scans became one `union all`; webhook selectors compile once
  per subscription; per-key KV gets are batched; WS gateways revalidate every 5 minutes instead of
  every 25 seconds.
- Web live store returns the same state when a KV put is unchanged (was ~5 full-table re-renders/s
  for 300 phones on a 60 s Expires); extra topic leases replay a cached snapshot instead of
  re-subscribing (was O(N²) on mount).

## Deferred with reasons (needs a decision or a larger change)

- Five `ON DELETE SET NULL` foreign keys were not made tenant-composite: a composite `SET NULL` would
  null `organization_id`, and PG15's `SET NULL (column)` is not expressible in drizzle-kit.
- `organization_sso_provider.provider_id` stays globally unique. better-auth uses it in the callback
  URL, so a per-org composite would need a derived global id; duplicates return 409 for now.
- Per-tenant named Asterisk ACLs were not built (they need one endpoint per tenant, which nothing
  generates); the multi-tenant section degrades to blocklist rendering with a warning instead.
- The sipd reaper still lists the whole `sip-dialogs` bucket per instance; a watch-backed index or
  leader lease is a design change. The reap now runs on a longer jittered interval.
- Engine ownership maintenance still does `keys()` + per-key `get`; the pass now skips foreign
  leases, which removes most round trips. A watch-backed cache is the full fix.
- The routing `explain` flag for discarded diagnostics needs both `packages/routing` and
  `apps/api/src/pbx/routing/routing.service.ts` landed together.
- `mediad BuildAnswer` Opus/PT-0 refusal needs a signature change across callers; the audit
  confirmed it is latent.
- The child-DELETE guard split (pin-sets/phrases on `.delete` vs `.write`) was left as is; the
  proposed fix lowered a permission with no bug behind it.
- Web CSP is report-only: the softphone WSS host and the signed recording URLs are per-deployment
  values that cannot be verified from the codebase. HSTS is enforced.

## Judgement calls to review

- Conference join destroys the bridge only when this leg created it; destroying unconditionally
  would end a meeting other members are already in.
- `releaseAll` gives the hangup cause only to the agent it belongs to rather than widening
  `QueueDialOutcome` to a per-attempt list.
- The voicemail "Messages…" row action gates on `voicemail.read.own` (it opens a list); play and
  edit gate on `listen.own` / `write.own` inside the dialog.
- `ENGINE_INSTANCE_ID` set to the literal `engine` is refused in production. Containers get
  `HOSTNAME`; a bare-metal production run must set one of the two.
- `dockerize` was removed from the API image in favour of `depends_on: service_healthy`.
- The branding `logoObjectKey` DTO field accepts only `null` (to clear the logo) rather than being
  removed, because there is no `DELETE /branding/logo` route.
