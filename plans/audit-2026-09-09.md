## The P0s worth knowing about

Security

- SSO: tenant IdPs were registered platform-wide with account linking on. An org admin controlling
  an IdP could assert another tenant's email and take over that account.
- `moh_class.streamUri` was rendered unvalidated into `musiconhold.conf`; a newline injected an
  `application=` line that Asterisk executes.
- mediad built the recording directory from unvalidated `orgId`/`callId`, so `../../..` escaped the
  recordings root.
- sipd accepted a replayed REGISTER `Authorization` with a different Contact within the nonce TTL,
  forking a victim's inbound calls to the attacker.
- `branding.logoObjectKey` was caller-supplied and then served unauthenticated from the shared media
  root; SVG logos were served inline on the API origin.
- api and engine held `$JS.API.>` in `config/nats.conf`, which made their enumerated NATS grants
  decorative (stream delete/purge, and reads of every KV bucket including registrations).
- Effect defect logging and `Effect.log` annotations bypassed redaction entirely.
- Unmatched WebSocket upgrades were never destroyed once an upgrade listener existed: an
  unauthenticated fd leak. The provisioning rate limiter ran after the secret check.

Correctness

- sipd's carrier profile was unreachable in its own default configuration (no listener means never
  matched), so every carrier INVITE got an unanswerable digest challenge.
- The engine's AOR fallback applied to off-net follow-me hops, external destinations and external
  queue agents, resolving them against the tenant registrations bucket instead of the trunk.
- One tenant's first `allow` ACL row flipped the shared Asterisk ACL section to allowlist mode with
  `deny 0.0.0.0/0`, locking every other tenant's phones out.
- The projection outbox was discharged even when every KV put failed (trunks, DID index, SIP ACL,
  queue membership), so a failed publish was never retried.
- `PUT …/reorder` violated the unique `(parent, ordinal)` index on 7 of 8 reorderable collections.
- `/healthz` did not see the sipd dialog feed; a dead feed meant no leg ever ended while the pod
  reported healthy. Live media events were dispatched unordered per leg.
- `planNodeReferences` omitted four edge kinds, so closure and cycle checks were blind to queue exit,
  call-flow day/night, stream fallback and dial-by-name branches.
- mediad never reaped held or muted sessions (a ringing leg after an engine crash leaked its port
  pair until restart) and grew the playback index on every hold.
- A data race in sipd's reaper heartbeat read live dialog fields off the owning goroutine.

## Performance highlights

- mediad transcode hot path: 3 allocations / 1120 B per packet down to 1 / 160 B (measured).
  Mixer socket writes moved outside the conference mutex; allocator binds outside its mutex.
- Engine queue polling collapsed from `callers × agents` KV gets per second to one fan-out per roster
  per poll; `rankOf` is a counting pass instead of a full re-sort per caller; routing-artifact and
  roster caches are TTL + LRU bounded.
- sipd registrar sweep no longer does a KV round trip per binding every 5 s; credential cache has
  O(1) eviction and single-flight; ACL replay compiles once instead of once per record.
- API: 21 serial per-delete existence scans became one `union all`; webhook selectors compile once
  per subscription; per-key KV gets are batched; WS gateways revalidate every 5 minutes instead of
  every 25 seconds.
- Web live store returns the same state when a KV put is unchanged (was ~5 full-table re-renders/s
  for 300 phones on a 60 s Expires); extra topic leases replay a cached snapshot instead of
  re-subscribing (was O(N²) on mount).

## Deferred with reasons (needs a decision or a larger change)

- Five `ON DELETE SET NULL` foreign keys were not made tenant-composite: a composite `SET NULL` would
  null `organization_id`, and PG15's `SET NULL (column)` is not expressible in drizzle-kit.
- `organization_sso_provider.provider_id` stays globally unique. better-auth uses it in the callback
  URL, so a per-org composite would need a derived global id; duplicates return 409 for now.
- Per-tenant named Asterisk ACLs were not built (they need one endpoint per tenant, which nothing
  generates); the multi-tenant section degrades to blocklist rendering with a warning instead.
- The sipd reaper still lists the whole `sip-dialogs` bucket per instance; a watch-backed index or
  leader lease is a design change. The reap now runs on a longer jittered interval.
- Engine ownership maintenance still does `keys()` + per-key `get`; the pass now skips foreign
  leases, which removes most round trips. A watch-backed cache is the full fix.
- The routing `explain` flag for discarded diagnostics needs both `packages/routing` and
  `apps/api/src/pbx/routing/routing.service.ts` landed together.
- `mediad BuildAnswer` Opus/PT-0 refusal needs a signature change across callers; the audit
  confirmed it is latent.
- The child-DELETE guard split (pin-sets/phrases on `.delete` vs `.write`) was left as is; the
  proposed fix lowered a permission with no bug behind it.
- Web CSP is report-only: the softphone WSS host and the signed recording URLs are per-deployment
  values that cannot be verified from the codebase. HSTS is enforced.

## Judgement calls to review

- Conference join destroys the bridge only when this leg created it; destroying unconditionally

- `releaseAll` gives the hangup cause only to the agent it belongs to rather than widening

- The voicemail "Messages…" row action gates on `voicemail.read.own` (it opens a list); play and

### What the live runs found and fixed

Correctness (each proved broken live, fixed with tests, re-proved live):

- Engine routing watch hung silently for hours: the engine and API NATS users lacked the `$JS.FC.>` flow-control
  reply grant, so ordered consumers stopped pushing without error. Grant added, plus a revision-based stale guard.
- KV listings that awaited a `get` inside `keys()` read one row instead of all, in the engine's channel scan, the
  API live snapshot and two publishers.
- sipd served the plaintext WS listener over TLS whenever WSS was enabled; sipd's ACL/trunk/presence watches died
  after a broker reconnect and never recovered; a revoked ACL rule stayed in force forever; sipd picked the SIP
  profile from the sender-supplied Request-URI, letting a trunk ACL entry turn another network's phones into
  digest-free carrier peers.
- A new org was handed another tenant's SIP realm; `ENGINE_SIP_REALM` removed, refusal by name when no domain is set.
- Tenant-uploaded prompts had never been playable on mediad (row id vs object key); default MOH and system prompts
  did not exist, so queues and IVRs played silence; the browser softphone sent DTMF as SIP INFO, so IVR digits never
  reached the far end; an unplayable IVR greeting hung up on the caller.
- Caller cancel never reached the ringing callee under the split plane; refused originates and every unanswered leg
  were filed as `answered` in the CDR; busy was relayed as 480; pickup bridged the caller unanswered; the softphone
  ignored auto-answer so paging never connected; park `*5` parked the presser and recalled the wrong party.
- A mediad crash stranded every call (the engine's hangup path needed mediad); a sipd crash left zombie calls; a dead
  engine's calls survived but were never billed. Fixed with sipd and engine instance leases and lease-fenced
  adoption: calls end in 1.3 s / 12.6 s after a plane dies, and a killed engine's calls are adopted in 12 s and billed.
- The `tsx` dev runner emitted no decorator metadata, so bare-class Nest injections were `undefined` in development;
  both apps now run on `@swc-node/register` and CI carries a DI-metadata guard.
- Every REGISTER burst was answered 403 when the credential RPC missed its deadline; the responder answered one
  lookup at a time behind three database transactions.

## 2026 completeness pass (2026-09-09 into 2026-09-10)

The September audit closed the gaps this codebase knew about. It could not close the gaps the codebase
had never heard of — the rules that changed in 2026 while the tree was being written. So this pass
began not in the repo but on the web: what does a multi-tenant hosted PBX with contact-centre basics
have to do, legally and commercially, to ship in late 2026? The answer was read out of primary sources
and turned into a numbered requirement list before a single grep was run, so the shape of the work came
from the outside rather than from whatever happened to be easy to find inside.

### What the research established

Twenty sources, read Sept 2026, fall into five groups. The full list with URLs is in
`plans/audit-2026-09-09/reports/GAP2026-map.md`.

**Robocall mitigation and traceback** (sources 1-5). The FCC's final rule on the Robocall Mitigation
Database (Federal Register 2026-00010, 6 Jan 2026), the 1 Jul 2026 fact sheet and the 27 Jul 2026 Wiley
alert add annual recertification, a filing fee, 2FA on the filing, a 10-business-day update rule, and —
the one that reaches the code — a certification that the provider _will respond to traceback requests
within 24 hours_. TelcoBridges' walkthrough of 47 CFR §64.6305 makes the operational point plainly:
after the September 2025 group order against twelve providers who certified that and missed it, a
traceback response is a real-time query against a live log store, not a forensic exercise on archived
logs. Viirtue's 2026 reseller guide closes the loop — a reseller serving end users is its own voice
service provider, owes its own filing, its own documented KYC, and the same 24-hour clock.

**STIR/SHAKEN** (6, 7). The 29 Apr 2026 _Enhancing STIR/SHAKEN_ fact sheet and draft FNPRM codify the
A/B/C attestation criteria and say a provider serving end users directly makes all attestation-level
decisions _regardless of whether it has an implementation obligation of its own_. Third-party signing
is allowed only if that provider makes the decision and the calls carry its certificate; delegate
certificates (ATIS-1000092) count as right-to-use evidence. Davis Wright Tremaine's June 2026 note on
the expanded KYUP rules says the same from the enforcement side. The consequence for a platform whose
carrier signs on its behalf is uncomfortable and unambiguous: the decision is ours even though the
signature is Telnyx's.

**Messaging** (8-10). Telnyx's toll-free verification docs make three business-registration fields
mandatory for every new submission from 17 Feb 2026; Telgorithm's 2026/2027 guide adds the Sept 2026
expansion requiring published privacy-policy and T&C URLs. The 10DLC docs give the diagnostic chain —
brand `identityStatus`, campaign `ACTIVE`, number assigned — that decides whether a message is
delivered or silently filtered. CTIA's Messaging Principles, contractually mandatory for A2P per
Holland & Knight (May 2026), and the FCC's April-2025 "any reasonable method" opt-out order per
Infobip, set the consent and STOP/HELP obligations.

**Recording, privacy and PCI** (11, 12, 20). Enzo Dialer's consent-state table (Jul 2026, verified
against RCFP) and SIPNEX's 2026 list give eleven to thirteen clear all-party states, Washington's
"reasonably effective recorded announcement" safe harbour, and _Kearney v. Salomon Smith Barney_
extending California's rule to interstate calls. Key IVR's 2026 PCI DSS guide and PCI Pal on DTMF
masking put requirements 3, 4, 7 and 10 directly on the recorder, and prefer preventing capture over
pausing by hand. GDPR Art. 17 and the ICO's right-to-erasure guidance require erasure without undue
delay by a verified requester, with a suppression log permitted.

**Security and the feature floor** (13-19). TelcoBridges' SBC guide ("use mTLS for carrier peering;
one-way TLS is not sufficient") and SIPTRUNK's 2026 secure-trunking piece ("modern implementations
should use TLS 1.3") set the transport bar, with anomaly detection and real-time fraud monitoring as
baseline. Nextiva, PanTerra, Capacity, AmplifAI and the Webex Contact Center release notes set the
commercial one: voicemail transcription, SMS/MMS in the base bundle, E911, porting, skills-based
routing, RONA, wrap-up and disposition codes, supervisor monitor/whisper/barge, callback, post-call
survey, real-time transcription and AI summaries.

### The outage, and its root cause### The migration ledger incident

While resetting a mis-applied migration, one pack ran a `delete` against `drizzle.__drizzle_migrations`
with an over-broad `created_at` predicate and removed **seven other packs' ledger rows**. It reported
this rather than papering over it. The repair recomputed each migration's hash _and_ name using the same
`readMigrationFiles` the migrator itself uses, re-filed them, and then verified that only that pack's own
two migrations were outstanding before applying anything.

The verification did not rest with the pack that caused it. The coordinator re-derived every migration
folder's sha256 and name and matched them against the ledger in all three databases: 6/6, 44/44 and
16/16, no orphan rows, nothing unapplied. No journal was hand-edited by anyone, and no pack's DDL was
re-run or lost. The migration lock protocol (`MIGRATION-LOCK-<package>`, `set -o noclobber`) held
everywhere it was used; the incident happened inside one pack's own lock window, not in a collision.
