# Calling-platform capability matrix

What a complete multi-tenant hosted PBX + contact-centre-basics platform (carrier = Telnyx SIP trunking
only) needs, and where this codebase stands on each item as of 2026-09-09, HEAD `3bd98f2` plus the
uncommitted fixes listed in the audit reports.

**Revised 2026-09-10 for the completeness pass.** Seventeen rows that read MISSING or PARTIAL were
re-verified against the working tree and are now PRESENT — each carries a file:line in its evidence
column. A new §9 carries the 2026 requirement set from `GAP2026-map.md`, one row per requirement.
Section numbering in §1-§8 is unchanged; §9 is appended, not interleaved.

**Status vocabulary**

- **PROVEN** — exercised live on the standing stack described in `STACK.md`; the evidence column names
  the report and its scenario.
- **UNPROVEN** — code exists with unit tests; no live run. The evidence column names the code and the test.
- **PRESENT** — verified on the current tree at the file:line in the evidence column. Used where a row
  was written as MISSING or PARTIAL before the September closure round and the 2026 pass, and the
  capability is now in the tree; where a live run also exists the evidence column names it.
- **PARTIAL** — the named half is missing.
- **MISSING** — searched, nothing found.
- **N/A** — with reason.

**Evidence rule applied throughout**: a status was never upgraded on inference. Where a report claims a
capability but no code or live artifact backs it, the row says so. Where two reports disagree, the later
one wins and the row says which (this happens three times: IVR playback, the wallboard socket, and the
browser transfer UI — all three were failing in the first pass and were fixed and re-proved later the
same day).

   are never adopted and **never billed**. Wire the untracked `engine-liveness.service.ts` /
   `channel-watch.service.ts` / `instance-liveness.watcher.ts` into `nats.module.ts` and `/healthz`, add
   `engine-instances` grants to `config/nats.conf` symmetric to the working `sip-instances` set, and give
   an orphaned `channels` entry an ownership contest. Specs mirroring `sipd-liveness.service.spec.ts`.
   Prove live by repeating the two-engine SIGKILL and asserting a CDR row exists.
2. **Backups and restore (M).** Nothing exists. Add a documented `pg_dump` / WAL-based procedure plus a
   restore-drill script under `.scripts/` covering all three logical databases, and a JetStream file-store
   snapshot for the durable streams (CDR, AUDIT, VOICEMAIL). Prove live by restoring into a scratch
   Postgres and reading back a smoke call's CDR.
3. **SIP REGISTER attempt lockout (S/M).** `apps/sipd/internal/registrar/authfailure.go` throttles the
   audit row, not the attempt — a credential spray runs at full rate. Add a source+account failure counter
   that returns 403 for a cooling window regardless of credential correctness, in the shape of the
   existing `nonceGuard`. Unit test in `internal/registrar`; prove live with a scripted spray followed by
   a legitimate REGISTER after the window.
4. **sipd profile selection by source address (M).** `E2E-resilience.md` §"The profile-selection hole":
   sipgo never sets `Destination()`, so an inbound request is matched by SOURCE, and one tenant's trunk
   ACL entry reclassifies another network's authenticated phones as digest-free carrier peers on UDP and
   TCP. Use sipgo's `TransportReadFilter` to stamp the local address, select by listener, then narrow the
   source step to listenerless external profiles. Go tests per profile/transport pair; prove live by
   re-creating the loopback allow and confirming internal 1601→1602 still works.
5. **Fax retry backoff, webhook correlation, and trunk password rotation (M).** Three P0s in
   `api-pbx-1.md`, all with file:line. `fax-send-worker.service.ts:166` burns the whole retry budget in
   ~15 s; a non-UUID `client_state` throws and loses every terminal status; re-provision rotates a live
   SIP password with no compensation. Fix, add tests beside `fax.test.ts`, then run a live send/receive.
6. **Conference moderation fan-out (S).** `conference-moderation.service.ts:138-149` abandons the fan-out
   at the first unreachable engine, so a moderator command silently fails while another instance holds the
   bridge. Treat only `unknown-conference`/`unknown-member` as authoritative; retry the rest. Then run the
   3-way conference scenario that no report has ever run.
7. **Measured concurrency (M).** No calls/s, concurrent-call, or registration figure exists anywhere. Build
   a pool runner around the existing `TestE2EHoldACallOpen` harness for 100 then 200 concurrent calls plus
   1 000 churning registrations, sampling pprof, goroutines, event-loop lag and the Postgres pool. This is
   a knowledge gap, not a code gap, but shipping a hosted PBX without it is not defensible.
