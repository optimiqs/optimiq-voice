## Cross-area: generated-file headers (packages/events/scripts/go-emitter.ts)

`GoFile.render()` (go-emitter.ts:192-204) emits, on every one of the 15 `*_gen.go` files:

```go
// Code generated by packages/events/scripts/generate-go.ts. DO NOT EDIT.
//
// Source of truth: packages/events/src (Zod) -> packages/events/schema (JSON Schema) -> here.
// Regenerate with `pnpm --filter @optimiq-voice/events codegen`.

// <per-file packageDoc lines, passed by generate-go.ts>
```

Assessment: the header is **not** the noisy part. Line 1 is the canonical `^// Code generated .* DO NOT EDIT\.$`
form that Go tooling matches — keep verbatim. The two extra lines are a legitimate provenance/regeneration
pointer, though they are repeated 15×; a tighter version would fold them into one:

```go
// Code generated by packages/events/scripts/generate-go.ts. DO NOT EDIT.
// Source: packages/events/src; regenerate with `pnpm --filter @optimiq-voice/events codegen`.
```

The real volume is in the emitted _bodies_, from string literals in generate-go.ts: the hangup-cause block
(generate-go.ts:294-398) is ~40 comment lines of prose, and `rpc_gen.go` carries 301 comment lines. Several
of those are the same policy this pass deduplicated in the hand-written half (e.g. the "a plain string type
rather than a closed enum" argument at generate-go.ts:294-299 restates envelope.go's additive-evolution rule).
Trimming them means editing the emitter string literals plus a `codegen` run — out of scope here.
